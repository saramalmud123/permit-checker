# מערכת הצלבת בעלות מול חתימות ומסירות דואר — פריסה ל-Vercel

## מה השתנה לעומת גרסת ה-Artifact

1. **הקריאה למודל השפה עברה לצד שרת** — `src/App.jsx` כבר לא קורא ישירות ל-
   `api.anthropic.com`. הוא פונה ל-`/api/extract` (הפונקציה ב-`api/extract.js`),
   ורק היא מחזיקה את מפתח ה-API ופונה החוצה.
2. **נוסף `middleware.js`** — אכיפת Basic Auth על כל נתיב באתר (גם הדף וגם ה-API),
   מבוססת על משתני סביבה בלבד.
3. **אין `console.log` עם תוכן קבצים** — בקוד השרת (`api/extract.js`) הלוגים
   כוללים רק מטא-דאטה כללית (סוג בקשה, קוד סטטוס). שגיאות מודפסות כהודעה כללית,
   בלי לצטט את תוכן השגיאה המקורי (שעלול להכיל טקסט מהמסמך).
4. **אין קידומת `VITE_`** — כל הסודות (`ANTHROPIC_API_KEY`, `BASIC_AUTH_USER`,
   `BASIC_AUTH_PASS`) מוגדרים ללא הקידומת הזו, ולכן אינם נכנסים לחבילת ה-JS
   שנשלחת לדפדפן.
5. **מיקום עיבוד (`vercel.json`)** — פונקציית `api/extract.js`, שהיא היחידה
   שמטפלת בתוכן הקבצים בפועל, מוצמדת לאזור Frankfurt (`fra1`) במקום לאזור
   ברירת המחדל של Vercel (בדרך כלל ארה"ב). ראו הסתייגות בסעיף "מגבלות" למטה —
   זו הפחתת סיכון חלקית, לא פתרון מלא.
6. **`api/_logger.js`** — עטיפת לוגים (`safeLog` / `safeLogError`) שמסננת
   אוטומטית מפתחות שנראים כמו PII (שם, ת.ז., כתובת, טקסט גולמי וכו') ומחליפה
   אותם ב-`[REDACTED]` לפני שהם נכתבים ל-console. `api/extract.js` עודכן
   להשתמש בה במקום ב-`console.log`/`console.error` ישירים.

## פריסה — שלב אחר שלב

1. **התקנה מקומית (אופציונלי, לבדיקה):**
   ```
   npm install
   cp .env.example .env.local   # ומלאו ערכים אמיתיים
   npm run dev
   ```
   שימו לב: Basic Auth מבוסס Edge Middleware לא תמיד רץ מקומית באותה צורה
   כמו בענן — הבדיקה האמיתית של ה-Auth היא אחרי הפריסה.

2. **דחיפה ל-Git repository** (GitHub / GitLab / Bitbucket).

3. **ייבוא הפרויקט ב-Vercel** (vercel.com → Add New Project → בחרו את ה-repo).
   Vercel תזהה אוטומטית שמדובר בפרויקט Vite.

4. **הגדרת משתני סביבה** ב-Project Settings → Environment Variables:
   - `ANTHROPIC_API_KEY`
   - `BASIC_AUTH_USER`
   - `BASIC_AUTH_PASS`

   ללא קידומת `VITE_` לאף אחד מהם.

5. **Deploy.** בכל push ל-branch הראשי, Vercel תבנה ותפרוס מחדש אוטומטית.

6. בכניסה הראשונה לאתר, הדפדפן יציג חלון התחברות סטנדרטי (Basic Auth) —
   יש להזין את `BASIC_AUTH_USER` / `BASIC_AUTH_PASS`.

## מגבלות ותזכורות אבטחה

- **Basic Auth הוא פתרון מינימלי**, מתאים לפיילוט/שימוש פנימי מצומצם.
  לשימוש רחב עם נתוני תושבים אמיתיים, מומלץ להחליף בהתחברות ארגונית (SSO).

- **מיקום עיבוד הנתונים — מה `fra1` פותר ומה לא:**
  הצמדת `api/extract.js` ל-Frankfurt (EU) פותרת רק את ה"קפיצה" הראשונה —
  היא מבטיחה שהשרת שמקבל את הקובץ מהדפדפן פועל באירופה ולא בארה"ב, ושישראל
  נהנית מהחלטת נאותות (adequacy decision) מול האיחוד האירופי לגבי זרימת
  מידע. אבל **הקפיצה השנייה** — הקריאה מ-`api/extract.js` אל שירות ה-API של
  Anthropic — עדיין יוצאת לתשתית של Anthropic עצמה, שאין לנו שליטה או מידע
  מדויק על מיקומה הגיאוגרפי. כלומר זו הפחתת סיכון חלקית בלבד, לא "פתרון
  residency" מלא. כמו כן, שימו לב:
  - הצמדת אזור שאינה ברירת המחדל (`fra1`) עשויה לדרוש מנוי Vercel בתשלום
    (Pro ומעלה) — בדקו זאת בחשבונכם, זה עלול להיכשל בשקט על תוכנית Hobby.
  - `middleware.js` (בדיקת ה-Basic Auth) רץ על "Edge Network" הגלובלי של
    Vercel בכל מקרה ולא ניתן להצמידו לאזור בודד — אך הוא רק בודק כותרת
    הרשאה ואינו נוגע בתוכן הקבצים, כך שזה פחות רלוונטי מבחינת חשיפת PII.
  - השאלה המשפטית האמיתית (האם מותר בכלל להעביר ת.ז./נסחי טאבו של תושבים
    לענן חיצוני, EU או לא) לא נפתרת ע"י שינוי קוד — היא עדיין דורשת אישור
    היועץ המשפטי/הממונה על הגנת הפרטיות ברשות.

- **לוגים (`api/_logger.js`)** — כל קריאה ל-`safeLog`/`safeLogError` מסננת
  שדות שנראים כמו PII וגם מחרוזות ארוכות באופן חריג (שעלולות להיות תוכן
  שחולץ ממסמך). זו הגנה שמכסה את הקוד הקיים בפרויקט, **אך היא אינה קסם**:
  אם מתכנת עתידי יוסיף `console.log(someVariable)` ישירות במקום להשתמש
  ב-`safeLog`, ה-redaction לא יחול. יש לאכוף בעבודת צוות (code review /
  linter) שכל לוג חדש בצד השרת עובר דרך `safeLog`.

- **המערכת אינה שומרת קבצים** — אין מסד נתונים; כל עיבוד מתבצע "on the fly"
  ומוחזר ללקוח.

- בדקו את תנאי השימוש העדכניים של Anthropic לגבי שמירת נתוני בקשות API,
  ואם נדרש - בררו לגבי הסכם Zero Data Retention ברמת ארגון.
